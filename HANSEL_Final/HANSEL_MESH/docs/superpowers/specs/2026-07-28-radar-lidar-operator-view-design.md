# HANSEL 레이더 LiDAR형 주행 화면 설계

## 1. 목표

IWRL6432BOOST 한 대가 제공하는 희소 3D 포인트와 거리-방위각 히트맵을 이용해,
붕괴현장의 저시정 환경에서 운전자가 전방 장애물의 좌우 위치와 거리를 판단할 수 있는
실시간 주행 화면을 만든다.

이 버전의 주 화면은 카메라 영상을 흉내 내지 않는다. 측정되지 않은 높이와 표면을
채워 넣지 않고, 실제 레이더 증거를 LiDAR형 탑뷰로 표시한다. 0~50cm 화면은 충돌
확대창으로만 사용하고, 고정 누설을 제외한 신뢰 가능한 장애물이 10cm 이하일 때만
거리 기반 빨강 경고를 낸다.

## 2. 결정 근거

2026-07-28 녹화 시각과 대응하는 레이더 로그 182프레임을 분석한 결과는 다음과 같다.

- 프레임 누락, 히트맵 누락, 장치 불연속은 모두 0이었다.
- 50cm 이내의 실제 장면 후보는 프레임당 평균 1.93점이었다.
- 전체 포인트의 64.3%는 50cm 밖이어서 기존 화면에서 폐기됐다.
- 약 9.77cm의 두 고정 포인트 군집 때문에 기존 `FRONT` 표시의 87.4%가 빨강이었다.
- 이 고정 군집을 진단상 제외하면 빨강 비율은 0.55%였고 최근접 거리 중앙값은
  36.0cm였다.
- 히트맵 거리 간격은 0.09765625m다. 기존 윤곽 로직이 12cm 미만을 제외한 뒤
  50cm 안에서 사용하는 히트맵 깊이는 사실상 19.5, 29.3, 39.1, 48.8cm 네 단계다.
- 기존 화면의 회색 벽 높이는 측정값이 아니라 거리가 가까울수록 크게 보이도록 만든
  합성값이다.
- 이전 윤곽을 최대 900ms 유지하지만 로봇 이동량을 보정하지 않아 선이 멈추거나
  갑자기 사라진다.

따라서 렌더링을 더 카메라처럼 꾸미는 것은 실제 공간 인식을 개선하지 못한다. 먼저
고정 누설을 제거하고, 50cm 밖의 데이터를 다시 사용하며, 측정 증거와 미확인 영역을
분리해야 한다.

## 3. 검토한 접근법

### 접근 A: 카메라형 희소-조밀 복원

16개 방위각 히트맵과 희소 3D 포인트 사이를 보간해 흑백 영상처럼 채운다.

- 장점: 익숙한 카메라 형태라 첫인상이 직관적이다.
- 단점: 히트맵에 높이 정보가 없고 보드의 명목 각도 분해능이 방위 약 29°,
  고도 약 58°라 대부분의 윤곽이 추정값이 된다.
- 판정: 붕괴현장 주행 화면에서는 허위 벽, 허위 통로 또는 장애물 누락을 유발할 수
  있으므로 채택하지 않는다.

### 접근 B: 레이더 단독 LiDAR형 즉시뷰

현재 프레임과 300ms 이하의 짧은 추적 결과를 로봇 기준 탑뷰에 표시한다.

- 장점: 현재 하드웨어만으로 구현하고 검증할 수 있으며, 실제 측정과 추정을 분리할
  수 있다.
- 단점: 로봇이 이동한 뒤의 장면을 장시간 누적할 수 없고, 광학 윤곽은 제공하지
  못한다.
- 판정: 이번 구현의 범위로 채택한다.

### 접근 C: 자세 보정 LiDAR형 누적지도와 Radar SLAM

엔코더와 IMU 자세로 여러 레이더 프레임을 세계 좌표에 누적하고, 이후 radar
scan-to-submap 정합과 loop closure를 추가한다.

- 장점: 실제 주행 중 구조가 점차 선명해지고, 헤드 유닛과 분리 유닛 위치를 같은
  지도에 기록할 수 있다.
- 단점: 정확한 시간 동기화, 레이더 외부 보정, 엔코더/IMU 입력 계약과 별도 검증이
  필요하다.
- 판정: 접근 B가 안정화된 뒤의 다음 단계다. 이번 버전은 이 입력을 받을 수 있는
  인터페이스 경계만 남긴다.

## 4. 구현 범위

### 포함

- 프로필별 빈 장면 고정 클러터 캘리브레이션
- 고정 포인트 군집과 고정 히트맵 배경의 제거
- 0~3m 로봇 기준 LiDAR형 탑뷰
- 0~50cm 충돌 확대창
- 실제 `x/y/z` 포인트와 거리 불확실성 표시
- 측정된 점유와 `UNKNOWN` 영역의 구분
- 10cm 고정 충돌 경고와 히스테리시스
- 300ms 이하의 짧은 표면 추적
- 입력 정지, 캘리브레이션 불일치, 히트맵 손실 상태 표시
- 기존 2026-07-28 기록을 이용한 회귀시험
- 향후 pose 입력과 유닛 분리 이벤트를 연결할 API 경계

### 제외

- 카메라형 표면 합성 또는 딥러닝 기반 조밀 복원
- 엔코더/IMU 드라이버 구현
- 세계 좌표 누적지도, loop closure, 전역 Radar SLAM
- 유닛 분리 위치의 실제 기록
- 모터 자동 정지 명령
- 로봇 폭을 이용한 통과 가능 경로 판정
- 레이더 펌웨어 변경과 새로운 chirp 프로필 튜닝
- 기존 카메라 화면과의 최종 통합 대시보드

## 5. 시스템 구조

### 5.1 `RadarFrontState`

기존 임무 JSONL을 따라가며 가장 최근의 완전한 `RadarFrame`과 상태 정보를 보관한다.
UART 소유권과 로그 계약은 변경하지 않는다. 서버 단계에서 50cm 밖 포인트를 버리지
않고 최소 3m까지 보존한다.

### 5.2 `RadarClutterModel`

프로필별 빈 장면 캘리브레이션을 담당하는 순수 Python 구성요소다.

입력:

- 여러 프레임의 원시 point cloud
- 복원 가능한 절대 dB 범위의 range-azimuth heatmap
- `profile_id`, 히트맵 크기, 거리 간격, 축 설정

출력:

- 반복되는 고정 point cluster의 중심, 공분산, 관측률
- 셀별 히트맵 중앙값과 MAD 기반 변동 폭
- 캘리브레이션 스키마 버전과 프로필 식별자

캘리브레이션은 장애물이 없는 상태에서 별도 명령으로 수행하고 파일로 저장한다.
프로필, 히트맵 크기, 거리 간격 또는 축 설정이 다르면 자동 적용하지 않는다.

### 5.3 `RadarSceneEstimator`

한 프레임의 레이더 데이터를 운전자용 장면 모델로 바꾼다.

처리 순서:

1. 비정상 수치, 후방점, 3m 밖 점을 제거한다.
2. `RadarClutterModel`에 일치하는 고정 point와 히트맵 배경을 제외한다.
3. point cloud의 실제 연속거리와 히트맵의 양자화된 거리 증거를 별도로 유지한다.
4. 각 방위 구간에서 배경 대비 유의한 가장 가까운 반사를 후보로 선택한다.
5. 후보를 최근 3프레임 안에서 연관시켜 최대 300ms만 유지한다.
6. 측정 불확실성 범위만큼 5cm 로컬 격자에 점유 확률을 분산한다.
7. 관측하지 못한 셀은 `UNKNOWN`으로 둔다. 반사가 없다는 이유로 `FREE`로
   표시하지 않는다.

히트맵은 높이를 만들지 않는다. `z`는 point cloud에서 실제로 제공된 점에만 붙인다.

### 5.4 `RadarHazardEvaluator`

충돌 경고는 장면 표시와 분리한다.

- 진입 임계값: 고정 클러터가 아닌 확인된 point track의 수평거리 `<= 0.10m`
- 확인 조건: 최근 3프레임 중 최소 2프레임에서 공간적으로 일치
- 해제 임계값: 같은 track이 `>= 0.13m`이거나 300ms 동안 재관측되지 않음
- 히트맵 0/1번 bin만으로는 빨강을 만들지 않음
- 상태 이름:
  - `DANGER`: 위 조건을 충족한 10cm 이하 장애물
  - `NORMAL`: 확인된 10cm 이하 장애물이 없음
  - `UNKNOWN`: 캘리브레이션이 없거나 유효 장면 증거가 없음
  - `SENSOR_FAULT`: 입력이 stale/fault/replay_end 상태

`NORMAL`은 통로가 안전하거나 비어 있다는 뜻이 아니다. 모터 제어에는 이 상태를 직접
연결하지 않는다. 10cm 안쪽은 현재 거리 bin 및 직접 누설과 겹치는 영역이므로 최종
로봇에는 범퍼나 별도 근접센서가 필요하다.

### 5.5 웹 API 장면 계약

기존 `/api/radar` 응답에 다음 `scene` 블록을 추가한다.

```json
{
  "scene": {
    "schema_version": 1,
    "pose_mode": "robot_relative",
    "calibration_status": "valid",
    "grid": {
      "resolution_m": 0.05,
      "forward_cells": 60,
      "lateral_cells": 60,
      "origin_forward_cell": 0,
      "origin_lateral_cell": 30,
      "encoding": "occupancy-u8-base64",
      "layout": "forward-major_lateral-minor",
      "unknown_value": 0,
      "data_base64": ""
    },
    "tracks": [
      {
        "track_id": 1,
        "forward_m": 0.36,
        "lateral_m": -0.12,
        "height_m": null,
        "distance_m": 0.38,
        "range_uncertainty_m": 0.098,
        "confidence": 0.82,
        "source": "heatmap",
        "age_ms": 76
      }
    ],
    "hazard": {
      "level": "NORMAL",
      "nearest_confirmed_m": 0.36,
      "threshold_m": 0.10,
      "reason": "no_confirmed_point_inside_threshold"
    },
    "diagnostics": {
      "raw_point_count": 11,
      "clutter_points_rejected": 2,
      "heatmap_cells_rejected": 31
    }
  }
}
```

`height_m`는 실제 `z`가 없는 히트맵 track에서 `null`이다. 향후 자세 보정 누적지도는
동일한 계약의 `pose_mode`를 `motion_compensated`로 바꾸고 grid 좌표 정의를
버전 증가로 확장한다.

grid byte의 인덱스는
`forward_index * lateral_cells + lateral_index`다. 값 `0`은 관측되지 않은
`UNKNOWN`이며 자유 공간이 아니다. 값 `1..255`는 점유 증거의 강도다.

## 6. 화면 구성

### 6.1 주 화면: 0~3m LiDAR형 탑뷰

- 화면 아래 중앙이 로봇과 레이더 원점이다.
- 전방 3m, 좌우 각 1.5m의 5cm 격자를 표시한다.
- 0.5m 간격 거리 링과 좌/정면/우 방위 기준선을 표시한다.
- 측정된 점유는 흰색 또는 청록색으로, 강한 최신 반사는 더 밝게 표시한다.
- point cloud 실측점은 테두리가 있는 선명한 마커로 표시한다.
- 히트맵 점유는 거리 및 각도 불확실성을 반영한 짧은 호 또는 타원으로 표시한다.
- `UNKNOWN`은 짙은 회색으로 두며 녹색 자유 공간을 만들지 않는다.
- 과거 track은 300ms 안에서 투명도가 빠르게 감소하고 그 이후 완전히 제거한다.
- 가장 가까운 신뢰 track 최대 5개에 실제 거리 또는 거리 구간을 표시한다.
- 실제 높이가 있는 point만 색 또는 작은 `z` 라벨로 구분한다.

### 6.2 보조창: 0~50cm 충돌 확대

- 10, 20, 30, 40, 50cm 링을 정확히 표시한다.
- 주 화면과 동일한 장면 모델을 확대할 뿐 별도 합성 윤곽을 만들지 않는다.
- 10cm 확인 track이 있을 때만 해당 track과 테두리를 빨강으로 표시한다.
- 10cm보다 먼 반사는 충돌 빨강으로 표시하지 않는다.
- 캘리브레이션이 없거나 센서가 끊기면 거리색 대신 상태 오버레이를 우선한다.

### 6.3 상태 및 진단

- `LIVE / DEGRADED / STALE / FAULT / REPLAY END`
- `CALIBRATED / CALIBRATION REQUIRED / PROFILE MISMATCH`
- 프레임률, 화면 나이, 원본 점 수, 제거된 클러터 수
- `ROBOT-RELATIVE`: 현재 버전이 SLAM 지도가 아니라는 표시

기존 가상 회색 벽 패널, 높이가 측정되지 않은 세로 면, 900ms 윤곽 hold는 제거한다.

## 7. 데이터 흐름

```text
TI UART
  -> sensors radar-live
  -> canonical mission JSONL + raw UART capture
  -> RadarFrontState
  -> RadarClutterModel
  -> RadarSceneEstimator
  -> RadarHazardEvaluator
  -> /api/radar scene contract
  -> LiDAR형 3m 탑뷰 + 50cm 충돌 확대창
```

향후 단계에서는 `RadarSceneEstimator` 앞에 시간 동기화된 encoder/IMU pose를 넣고,
로봇 기준 track을 rolling-map 좌표로 변환한다. 유닛 분리 이벤트는 당시 pose와
공분산을 저장한다.

## 8. 오류 및 안전 처리

- 캘리브레이션 파일 없음: 고정 클러터를 임의로 숨기지 않고
  `CALIBRATION REQUIRED`; 주행 검증을 허용하지 않는다.
- 프로필 불일치: 캘리브레이션 적용 중단, `PROFILE MISMATCH`.
- 히트맵 누락: point-only 모드로 강등하고 `DEGRADED`.
- point cloud 누락: 히트맵 점유는 표시하지만 10cm 거리 빨강은 만들지 않는다.
- 0.75초 이상 새 정상 프레임 없음: `STALE`.
- 2초 이상 없음 또는 소스 오류: `FAULT`.
- stale/fault/replay_end: 과거 점유를 흐리게 남기지 않고 정지 오버레이를 표시한다.
- API schema 불일치 또는 grid decode 실패: 장면을 그리지 않고 오류 상태를 표시한다.
- 반사 없음: `UNKNOWN`; `FREE`, `SAFE`, 녹색 통로로 표시하지 않는다.

## 9. 시험 전략

### 9.1 단위시험

- 캘리브레이션 profile/shape/range-step 일치와 불일치
- 반복 point cluster 식별과 비반복 장면점 보존
- 히트맵 median/MAD 배경 제거
- 최근 3프레임 중 2프레임 track 확인
- 300ms track 만료
- 10cm 진입 및 13cm 해제 히스테리시스
- 히트맵 단독 근거리 bin이 빨강을 만들지 않는 동작
- `UNKNOWN`, `DEGRADED`, `STALE`, `FAULT` 전이
- occupancy base64 크기와 좌표 변환

### 9.2 기록 기반 회귀시험

2026-07-28 대응 구간에서 대표 프레임을 작은 fixture로 추출한다.

- 약 9.77cm 고정 두 군집이 calibration 후 scene track과 hazard에서 제외된다.
- 기존에 보이던 12~50cm 비고정 point의 90% 이상이 유지된다.
- 고정 클러터 때문에 발생한 거리 빨강 비율이 87.4%에서 5% 미만으로 감소한다.
- 50cm 밖 포인트가 3m 주 화면에 다시 나타난다.
- 마지막 관측 후 300ms를 넘은 선이나 track이 남지 않는다.

### 9.3 정적 실측시험

넓고 반사가 단순한 공간에서 큰 금속 반사판을 사용한다.

- 정면 0.2, 0.3, 0.5, 1, 2, 3m
- 좌/중/우 각 위치
- 높이 상/중/하
- 각 위치에서 최소 10초 기록

point cloud는 보정 후 실측거리 오차를 기록하고, heatmap 거리는 9.77cm bin
불확실성 구간으로 표시되는지 확인한다. 광학 자의 외곽이 아니라 레이더 안테나 기준점을
사용한다.

### 9.4 10cm 경고시험

빈 장면 캘리브레이션 후 큰 반사판을 20cm에서 5cm까지 2cm 간격으로 이동한다.

- 10cm보다 먼 확인 point에서 거리 빨강이 발생하지 않는다.
- 10cm 이하의 비클러터 point가 최근 3프레임 중 2프레임 검출되면 빨강이 발생한다.
- 장애물을 13cm 이상으로 이동하면 빨강이 해제된다.
- heatmap 0/1번 bin 포화만으로는 빨강이 발생하지 않는다.
- 감지되지 않는 10cm 안쪽 영역을 안전으로 표시하지 않는다.

### 9.5 이동시험

레이더를 직선으로 천천히 전진시키며 실물과 화면을 함께 녹화한다.

- 고정 track이 화면에 300ms 이상 멈춰 있지 않는다.
- 접근 중 같은 track의 거리 라벨이 감소하거나, 연관이 끊기면 즉시 `UNKNOWN`으로
  사라진다.
- 서로 다른 반사를 하나의 연속 벽으로 강제 연결하지 않는다.
- 10분 연속 실행에서 프레임률 중앙값이 8Hz 이상이고 누락·메모리 증가를 기록한다.

## 10. 합격 기준

1. 주 화면은 0~3m 데이터를 표시하고 50cm 밖 포인트를 서버에서 폐기하지 않는다.
2. 50cm 화면은 별도 확대창이며 충돌 빨강 진입값은 정확히 0.10m다.
3. 기록 fixture의 고정 약 9.77cm 군집은 유효 캘리브레이션에서 hazard에 참여하지
   않는다.
4. 거리 기반 빨강은 확인된 비클러터 point track만 만들 수 있다.
5. 측정되지 않은 높이와 면을 생성하지 않는다.
6. 마지막 관측 후 300ms를 넘긴 윤곽 또는 track을 그리지 않는다.
7. 반사 없음과 캘리브레이션 없음은 안전이 아니라 `UNKNOWN`으로 표시한다.
8. stale/fault/replay_end에서 즉시 정지 오버레이를 표시한다.
9. 기존 Python 전체 테스트와 새 단위·회귀시험이 모두 통과한다.
10. 실제 정적·이동 시험 결과는 프레임률, 거리 오차, 경고 진입/해제와 함께
    임무 로그로 보존한다.
